# 시나리오 기반 판정 플레이테스트 자료 설계

## 의도

CoC-Bot의 기존 명령을 한 번의 짧은 세션에서 확인하고, 플레이어의 자유 서술을 시나리오가 요구하는 기능치·주사위 판정·후속 서술로 연결하는 다음 기능의 요구사항을 구체화한다. 자료는 사용자가 지정한 KPC 1명과 PC 1명으로 플레이할 수 있어야 한다.

## 목표

- 완전히 새로 만든 분기형 CoC 7판 단편 시나리오를 작성한다. 작업명은 **「유리파 관측소」**로 한다.
- 시나리오는 조사, 일반 기능 판정, 푸시, SAN 손실, 대립, 낭독 투표가 자연스럽게 시험되도록 구성한다.
- PC와 KPC의 캐릭터 자료를 현재 `sheet_parser.py`가 요구하는 한국어 라벨·숫자 값·스킬 항목에 맞춘다.
- 테스트 계획은 기존 기능의 실제 동작과 시나리오 문맥 기반 자동 판정·분기 서술이라는 미구현 요구를 구분한다.
- 결과물을 별도 브랜치에 문서로 추가하고 커밋한다.

## 목표에 포함하지 않는 것

- 이번 작업에서 봇의 `/행동`, 프롬프트, DB 스키마 또는 판정 규칙을 구현·수정하지 않는다.
- Google Docs/Sheets 계정에 실제 파일을 생성하거나 Discord 서버에서 명령을 실행하지 않는다. 로컬 자료를 옮겨 넣을 수 있도록 입력 구조와 절차를 문서화한다.
- 특정 출판 시나리오나 기존 캐릭터를 변형하지 않는다.

## 접근 방법

1. **원샷 자료집:** 한 장면에서 주요 기능 몇 개만 확인한다. 작성은 빠르지만 여러 명령과 분기 동작을 한 번에 시험하기 어렵다.
2. **분기형 시나리오 플레이테스트 묶음 (선택):** 여러 장면에서 조사·스킬·SAN·대립·낭독 흐름을 연결하고, 성공·실패에 따라 서로 다른 다음 서술을 정리한다. 이번 요청의 “행동 지문에 따라 주사위를 고르고 스토리를 이끈다”는 목표를 가장 직접적으로 시험한다.
3. **규칙 실험장:** 각 기능을 독립된 짧은 사례로 나열한다. 기능 단위 확인은 쉽지만 하나의 이야기가 선택과 결과를 연결하는 경험을 평가하기 어렵다.

사용자는 분기형 시나리오 구성을 선택했다. “캐틀리에 부름”은 대화 맥락에 따라 **크툴루의 부름(CoC 7판)**을 뜻하는 것으로 해석했다.

## 자료 형식과 구현 맥락

- 로컬 Markdown 문서로 작성한다. 시나리오 장면 제목은 Google Docs로 옮길 때 H1(부), H2(장면), H3(`Keeper` 낭독 구간)으로 지정할 수 있게 작성한다. 현재 `scenario_parser.py`는 이 제목 계층과 Keeper 구간의 문단만 읽는다.
- 캐릭터 표는 `sheet_parser.py`의 필수 항목(이름, 직업, 나이, 성별, 거주지, 출생지, 8개 능력치)과 허용된 스킬 이름을 사용한다. 각 라벨은 Google Sheets에서 왼쪽 셀, 값은 바로 오른쪽 셀에 둘 수 있게 제공한다.
- 플레이테스트 문서는 각 사례마다 입력 지문, 예상 판정/주사위, 성공 분기, 실패 분기, 현재 봇에서 가능한지, 관찰할 결과를 기록한다.
- 시나리오의 롤 결과 분기는 테스트 데이터 수준의 명시적 기대값이다. 현재 봇은 장면별 판정 규칙을 저장하거나 결과에 맞춰 Keeper 서술을 선택하지 않는다. 이 부분은 다음 구현을 위한 acceptance criteria로 표시한다.

## 설계 제약과 중요한 경계

- `/행동`은 현재 사용자 지문을 Gemini에 보내지만 장면 문맥 인자는 빈 문자열이다. 스킬 판정은 사용자의 PC 스킬을 조회해 자동 수행할 수 있으나, 시나리오에 기록한 주사위 식이나 성공·실패 서술 분기는 읽지 않는다.
- `/판정`은 스킬값·보너스·페널티를 직접 받으며, 실패하면 판정을 실행한 사용자만 푸시할 수 있다.
- `/산정`은 현재 PC의 SAN을 바꾸고 `/대립`은 두 기능값을 인자로 받는다. `/낭독시작`은 Keeper와 참가 PC가 각 문장에 2/3 동의해야 진행한다. KPC는 투표 로스터에 포함되지 않는다.
- PC 1명과 Keeper 1명으로 시작하면 투표 가능 인원은 둘이므로 두 사람 모두 투표해야 진행된다. KPC는 이야기 속 캐릭터이지 Keeper 플레이어와 동일한 역할이 아니다.
- 캐릭터 수치와 규칙 해석은 플레이테스트 편의를 위한 제안이며, CoC 정식 규칙 또는 공식 시나리오를 대체한다고 주장하지 않는다.

## 산출물

- 새 시나리오 원고와 장면별 Keeper 낭독 텍스트
- PC 1명, KPC 1명의 시트 입력 자료와 이야기 속 역할
- 봇 전체 기능의 실행 순서, 명령별 기대 결과, 미구현 기능의 기준을 담은 플레이테스트 문서
- 브랜치 `docs/scenario-aware-branching-playtest`의 커밋

## 남은 작성 선택

- 장면 수와 세션 길이는 한 번의 짧은 테스트(대략 60–90분)를 목표로 builder가 조정한다.
- 시나리오 결과는 완전한 성공·불완전한 성공·실패가 모두 이후 이야기에 연결되도록 작성한다.
- 민아는 봇/보조 진행자의 이름으로 테스트 문서에서 사용한다. 기존 코드가 해당 이름이나 역할을 구현했다는 뜻은 아니다.
