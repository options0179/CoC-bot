# CoC 판정 디스코드 봇 — 설계 스펙

- 날짜: 2026-08-31
- 저장소: https://github.com/options0179/CoC-bot.git

## 목적

Call of Cthulhu 7판 룰의 판정 계산을 자동화하는 디스코드 슬래시 커맨드 봇.
캐릭터시트/시나리오 진행은 다루지 않는다 (사람 키퍼가 직접 진행). 여러 서버에
공개 배포하는 것을 전제로 한다.

## 범위

**포함**
- 기본 스킬 판정 (d100 vs 스킬값, 보너스/페널티 주사위, 성공등급 판정)
- SAN 체크 (성공/실패에 따른 SAN 손실 다이스 계산)
- 대립판정 (Opposed Roll)
- 푸시 롤 (Pushed Roll) — 실패한 판정 결과에 버튼으로 재도전

**제외 (스코프 밖, 필요해지면 별도 스펙으로)**
- 캐릭터시트 저장/관리
- 시나리오 데이터 관리, 전투/대미지 자동화
- LLM 기반 키퍼 자동 진행

## CoC 7판 규칙 요약 (구현 기준)

- **판정**: d100을 굴려 스킬값 이하면 성공. 성공등급 — 크리티컬(1), 익스트림(스킬값/5
  이하), 하드(스킬값/2 이하), 일반(스킬값 이하), 실패, 펌블(스킬값<50이면 96-100,
  아니면 100).
- **보너스/페널티 주사위**: 10의 자리 주사위를 추가로 굴려 보너스는 낮은 값, 페널티는
  높은 값 채택. 최대 2개까지 중첩 가능하며 보너스·페널티는 서로 상쇄된다.
- **SAN 체크**: 1D100 ≤ 현재 SAN이면 성공(경미한 손실), 실패하면 더 큰 손실. 손실식은
  `성공손실/실패손실` 형식(예: `1/1d4+1`)으로 입력받아 파싱.
- **대립판정**: 양측이 각자 판정, 더 높은 성공등급이 승리. 동률이면 원 스킬값이 높은
  쪽이 승리. 푸시 불가.
- **푸시 롤**: 실패한 판정을 한 번 더 시도. Luck/SAN/전투/대미지 판정은 푸시 불가
  (이번 스코프에는 전투/대미지가 없으므로 판정·대립판정만 대상).

참고: [CoC 7e 스킬체크 보너스/페널티 다이스](https://basicroleplaying.org/topic/26060-clarification-about-bonuspenalty-dice-in-coc-7th-edition/),
[CoC 7e 치트시트](https://mythos.wiki/index.php/Call_of_Cthulhu_7th_Edition_Cheat_Sheet),
[SAN 체크 규칙](https://trpgline.com/rules/coc7/sanity)

## 아키텍처

상태 없는(stateless) 단일 프로세스 봇. 캐릭터 데이터를 저장하지 않으므로 DB를 두지
않는다 — 스킬값·SAN값은 매 커맨드 호출 시 인자로 받는다. 유일한 예외는 푸시 롤로,
discord.py의 `View`/`Button` 컴포넌트가 판정 결과 메시지에 붙어 직전 롤 정보를
메모리에 들고 있다가 클릭 시 재판정한다 (수 분 후 타임아웃, 프로세스 재시작 시
소멸 — 허용 가능한 손실).

DB가 없으므로 배포 비용은 사실상 프로세스 하나를 24/7 띄우는 비용뿐이다. 저사양
VPS(예: 1 vCPU / 512MB급) 또는 무료/저가 티어의 컨테이너 호스팅으로 충분하다.

## 컴포넌트

- `dice.py` — 핵심 판정 로직 (discord 비의존, 순수 함수)
  - d100 굴림, 보너스/페널티 주사위 처리
  - 성공등급 판정
  - `XdY+Z` 다이스 표기 파서
- `bot/cogs/check.py` — `/판정 스킬값 [보너스] [페널티]`
- `bot/cogs/sanity.py` — `/산정 현재san 손실식`
- `bot/cogs/opposed.py` — `/대립 내스킬 상대스킬`
- `bot/embeds.py` — 한국어 임베드 포맷 공통화
- `bot/main.py` — 봇 엔트리포인트, 커맨드 트리 동기화, 전역 에러 핸들러

## 데이터 흐름

1. 사용자가 슬래시 커맨드로 스킬값 등 파라미터 입력
2. cog가 `dice.py` 순수 함수 호출 → 결과(굴림값, 성공등급 등) 반환
3. `embeds.py`로 포맷 후 응답 전송 (판정 실패 시 푸시 버튼 첨부)
4. 푸시 버튼 클릭 시 View 콜백이 저장해둔 원 판정 정보로 재판정, 메시지 갱신

## 에러 처리

- 스킬/SAN 값 범위(0~100) 검증 실패 → ephemeral 오류 메시지
- 다이스 표기 파싱 실패 → ephemeral 오류 메시지 (형식 예시 포함)
- 그 외 예외는 커맨드 트리 전역 에러 핸들러에서 로깅 후 ephemeral 안내

## 테스트

`dice.py`는 discord 비의존 순수 함수이므로 pytest 유닛 테스트로 검증
(성공등급 경계값, 보너스/페널티 상쇄, 다이스 파서, SAN 손실 계산). 디스코드
연동은 수동 확인.

## 배포 / 환경

- 필요한 시크릿: `DISCORD_TOKEN` (봇 토큰) — 필요 시점에 대화창으로 요청
- `applications.commands` 스코프로 봇 초대, 글로벌 슬래시 커맨드 동기화
- Dockerfile 한 장으로 어디서든 실행 가능하게 구성 (저비용 VPS/컨테이너 호스팅 고려)
- `.env.example` 제공, 실제 `.env`는 `.gitignore`
