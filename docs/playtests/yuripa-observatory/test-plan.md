# 유리파 관측소 — CoC-Bot 초보자 플레이테스트 안내

## 무엇을 확인하나요?

이 테스트는 한 개의 짧은 이야기를 진행하며 현재 봇이 지원하는 기능과 아직 자동화되지 않은 기능을 구분합니다. 특히 플레이어가 자유롭게 적은 행동을 보고 민아(봇)가 필요한 기능치와 주사위를 고른 뒤, 성공·실패에 맞는 이야기 분기를 자동으로 이끄는 기능이 현재 구현되어 있는지 확인합니다.

**중요한 현재 한계:** `/행동`은 입력 문장을 Gemini에 보내 판정 필요 여부와 스킬을 분석하고, 필요하면 등록된 PC의 해당 기능치를 가져와 d100 판정을 굴립니다. 그러나 현재 장면의 시나리오 본문·Keeper 메모·분기 표를 읽지 않으므로, 어떤 수치가 이야기상 필요한지 정답을 보장하거나 성공/실패 결과로 다음 문장을 선택하지 않습니다. 이 테스트에서는 이 차이를 관찰하고 기록합니다.

## 용어를 쉽게 설명하면

| 용어 | 쉬운 뜻 | 이번 테스트에서 |
|---|---|---|
| 봇 | Discord 안에서 명령을 처리하는 프로그램 | 주사위·캐릭터·시나리오 등록을 수행합니다. |
| 슬래시 명령 | `/`로 시작하는 Discord 기능 버튼/명령 | 예: `/시나리오시작`, `/판정` |
| 시나리오 | Keeper가 장면과 규칙을 정리한 이야기 원고 | Google Docs 링크를 등록합니다. |
| PC | 플레이어가 맡는 주인공 | 한서윤, 참가자로 등록합니다. |
| KPC | Keeper가 맡는 주요 등장인물 | 윤태오, 시나리오 캐릭터로 등록합니다. |
| 기능치 | 특정 일을 해낼 가능성을 0–100 숫자로 나타낸 값 | 관찰력 65, 자료조사 60 등입니다. |
| d100 판정 | 1–100 숫자를 기능치와 비교하는 주사위 판정 | 굴림이 기능치 이하이면 성공합니다. 더 낮은 결과는 어려운 성공입니다. |
| SAN | 무서운 일을 겪을 때 정신이 흔들리는 정도를 나타내는 수치 | `/산정`으로 굴리고 PC의 현재 값이 바뀝니다. |
| 푸시 | 실패한 판정을 더 위험한 상황을 감수하고 한 번 더 시도 | `/판정` 결과의 푸시 버튼으로 시험합니다. |
| SQLite | 봇이 로컬 파일에 캐릭터/시나리오 진행 상태를 보관하는 데이터베이스 | 등록한 PC와 현재 SAN 등이 저장됩니다. |

## 봇에서 보이는 흐름

```mermaid

  A[Keeper가 Google Docs 시나리오 등록] --> B[현재 채널에 시나리오 배정]
  C[플레이어가 Google Sheets PC 등록] --> D[PC가 채널 시나리오 참가]
  E[Keeper가 Google Sheets KPC 등록] --> F[시나리오 등장인물로 저장]
  B --> G[행동 지문 입력]
  D --> G
  F -. 이야기 참고 .-> G
  G --> H[Gemini가 의도와 스킬 분석]
  H --> I[필요하면 PC 기능치로 d100 굴림]
  I -.현재는 자동 연결 안 됨. Keeper가 수동 해석 .-> J[성공·실패 분기 서술]
  I --> K[별도 명령: SAN·대립·푸시]
```

## 등록 전 준비

1. 봇이 있는 서버가 **실수로펑한그림쟁이서버**인지 확인합니다.
2. 이 서버에는 `#test` 채널이 없습니다. 현재 비어 있는 `#이벤트`에서 `/시나리오조회`를 실행해 기존에 배정된 시나리오가 없는지 확인합니다. 이미 배정되어 있으면 이 채널을 바꾸지 말고 Keeper와 함께 빈 테스트 채널을 찾습니다.
3. 시나리오와 시트는 봇이 공개 export URL로 읽습니다. 등록용 Google Docs/Sheets는 ‘링크가 있는 모든 사용자’가 읽을 수 있어야 합니다. 캐릭터 시트에는 이 가상 플레이테스트용 수치만 담습니다.
4. 시나리오를 만든 계정으로 `/시나리오등록 제목: 유리파 관측소 - 플레이테스트`를 실행합니다.
5. 같은 Keeper 계정으로 `/시나리오시작 시나리오: 유리파 관측소 - 플레이테스트`를 실행해 현재 채널에 바인딩합니다. 별도의 `/채널등록` 명령은 없으며, 이 명령이 채널 등록 역할을 합니다.
6. PC 플레이어가 `/캐릭터등록 링크:<한서윤 시트 URL>`을 실행한 후 `/시나리오참가`를 실행합니다.
7. Keeper가 `/시나리오캐릭터등록 시나리오: 유리파 관측소 - 플레이테스트 직책: KPC 링크:<윤태오 시트 URL>`을 실행합니다.
8. `/시나리오조회`로 시나리오와 참가 PC를 확인합니다.

## 테스트 진행 순서

| 단계 | 실행 | 입력 또는 방법 | 확인할 것 |
|---|---|---|---|
| A. 등록 | `/시나리오등록` | Google Docs URL | 시나리오 이름과 장면 수가 성공 메시지에 나오는가? |
| B. 채널 연결 | `/시나리오시작` | 등록한 고유 시나리오 이름 | 현재 채널이 배정됐는가? 기존에 다른 시나리오가 있으면 중단되는가? |
| C. 캐릭터 | `/캐릭터등록`, `/시나리오캐릭터등록` | 한서윤 PC, 윤태오 KPC Google Sheets URL | 한국어 라벨과 오른쪽 숫자가 읽히는가? PC와 KPC가 각자 역할로 조회되는가? |
| D. 참가 | `/시나리오참가`, `/시나리오조회` | PC 소유 계정으로 참가 | 참가자 목록에 PC가 표시되는가? KPC는 투표 로스터가 아닌가? |
| E. 낭독 | `/낭독시작` | Keeper 및 참가 PC가 문장마다 투표 | 둘 다 동의할 때 다음 문장으로 넘어가는가? PC 1명과 Keeper라면 두 표가 필요합니다. |
| F. 자유 행동 | `/행동` | “창틀과 모래를 살펴 발자국 방향을 비교한다.” | 모델이 관찰력을 선택하고 65를 사용해 판정하는가? 장면에 따라 결과를 바꾸는가? |
| G. 조사 | `/행동` | “녹음 날짜를 기상 기록과 대조한다.” | 자료조사 선택 여부와 60 사용 여부를 확인합니다. 다른 스킬이 나오면 기록합니다. |
| H. 수동 판정/푸시 | `/판정 스킬값:60` | 실패하면 원 판정자가 푸시 버튼 클릭 | d100 결과가 기능치 기준으로 성공 등급을 보이는가? 실패한 사람만 푸시 가능한가? |
| I. SAN | `/산정 손실식:0/1d4` | 녹음을 끝까지 들은 것으로 진행 | 굴림 결과에 따라 PC SAN이 실제로 줄고 다음 조회에도 반영되는가? |
| J. 대립 | `/대립 내스킬:50 상대스킬:50` | 태오에게 송신기를 놓으라고 설득 | 대립 판정이 두 값을 받고 결과를 보여주는가? 이야기 분기는 자동 선택되지 않는가? |
| K. 분기 관찰 | Keeper가 실제 판정 결과에 따라 시나리오 분기 표를 대조 | 성공·실패 각각을 가능한 두 번의 진행에서 확인 | 현재는 Keeper가 수동으로 다음 문장을 고릅니다. `/행동` 결과가 분기 메모를 자동으로 반영하지 않는지 확인합니다. |

### 테스트 팁

- d100은 무작위라 특정 성공/실패를 강제로 만들 수 없습니다. 우선 나온 결과를 기록하고, 푸시는 실패가 나왔을 때만 선택하세요.
- `/행동`은 Gemini API를 호출하므로 키 설정과 외부 모델 응답에 의존합니다. 다른 명령은 보통 Gemini 키 없이도 시험할 수 있습니다.
- Keeper와 PC가 같은 Discord 계정이면 투표 시스템에서 서로 다른 두 참가자로 보이지 않을 수 있습니다. 서로 다른 계정의 Keeper와 PC가 있어야 설계된 ‘두 표’ 조건을 완전히 확인합니다. KPC는 투표하지 않습니다.
- `#이벤트` 채널을 시나리오에 배정하면 그 채널에 저장 상태가 남습니다. 테스트 후 정리 명령이 없으므로 반드시 `/시나리오조회`로 확인하고, 테스트를 위해 새 시나리오만 추가하세요.

## 이번 테스트의 기대값

### 현재 동작 확인 가능

- Docs/Sheets를 읽어 시나리오·PC·KPC를 저장합니다.
- 특정 Discord 채널을 시나리오에 연결하고 PC 참가자를 기록합니다.
- `/행동`이 자연어 입력에서 판정 필요 여부와 스킬을 분석해 PC의 스킬값으로 d100 판정을 수행합니다.
- `/판정`과 실패 후 푸시, `/산정`과 SAN 갱신, `/대립`, `/낭독시작`의 기본 규칙을 확인합니다.

### 현재 미구현 (목표 기능)

- 시나리오 장면의 지문·Keeper 메모를 `/행동`의 장면 문맥으로 전달하기.
- 행동 묘사와 분기 조건에 맞는 기능치 및 보너스/페널티 다이스를 결정하기.
- 굴림 결과를 장면 분기와 연결해 후속 이야기 문장을 자동 선택하기.
- 봇이 선택한 수치/주사위/분기 이유를 플레이어가 이해하도록 설명하기.

미구현 항목이 동작하지 않는 것은 이번 테스트에서 봇의 장애가 아니라, 다음 제품 기능의 기준선을 확인한 것입니다.

## 종료 후 초보자 복습

- 능력치/기능치는 캐릭터 시트에 저장하고, 주사위 굴림은 행동 때마다 결과를 냅니다.
- “API 키가 필요하다”는 말은 봇이 Gemini라는 외부 AI 서비스에 요청을 보낼 때 본인임을 증명하고 사용량을 기록하는 비밀 열쇠가 필요하다는 뜻입니다. 키가 만료·폐기·잘못 입력되면 `/행동`의 분석 요청은 실패할 수 있습니다. 이 오류는 CoC 주사위 규칙 오류와 별개입니다.
- 시나리오를 등록했다고 해서 봇이 원고 속 규칙을 모두 이해하는 것은 아닙니다. 지금 등록기는 Keeper 낭독 문장을 장면으로 보관하고, `/행동`은 빈 장면 문맥으로 분석합니다.

## 플레이테스트 기록

- 실행 상태: 로컬 자료 검증 완료, Google Docs/Sheets 파일은 비공개로 생성, Discord 등록/플레이 미실행
- 사유: 봇 등록기는 Google 파일을 ‘링크가 있는 사용자’에게 읽기 공개해야 합니다. 테스트 캐릭터 자료와 시나리오를 외부 공개하는 권한 변경에 대해 사용자의 확인을 기다리고 있습니다.
