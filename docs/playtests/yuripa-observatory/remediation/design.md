# 시나리오 인식 플레이와 로컬 실행 안정화 설계

## 목적

자유 서술 행동을 현재 시나리오 장면의 판정 규칙과 연결하고, 실제 굴림 결과에 맞는 분기 서술을 채널에 남긴다. Gemini 장애와 봇 재시작이 플레이 기록을 끊지 않도록 응답과 낭독 동작을 안정화한다.

## 접근 검토와 선택

1. 현재 장면의 대사만 Gemini에 보내기: 작고 빠르지만, 기능 선택과 분기 문구가 여전히 모델의 추정에 의존한다.
2. 장면별 판정·성공/실패 결과를 시나리오 데이터로 명시하고, Gemini는 행동을 그 규칙에 연결하며 봇은 판정과 분기 선택을 수행하기: 시나리오 문서 형식 변경이 필요하지만 결과가 검증 가능하고 재현 가능하다.
3. 모든 행동·대사·장면 이동을 생성형 모델이 결정하기: 자유롭지만 규칙 준수와 결과 재현이 어렵다.

**선택:** 2번. 모델은 입력을 등록된 규칙 ID에 연결하는 데만 쓰고, 기능값 확인·주사위·성공 등급·분기 선택은 코드가 처리한다. 어떤 규칙에도 안전하게 연결할 수 없으면 근거 없는 굴림을 만들지 않고 수동 판정 안내를 한다.

## 범위

- Google Docs의 기존 Keeper 낭독 구간과 호환되게 장면별 행동 규칙과 결과 문구를 파싱한다.
- `/행동`이 채널의 시나리오 진행 위치, 현재 장면, 참가 PC 기능값, 장면 규칙을 읽는다.
- 모델의 선택을 알려진 규칙 ID 및 등록된 기능으로 검증한 뒤 굴림과 결과 분기를 표시한다.
- Gemini 네트워크·과부하·제한시간·응답 형식 오류를 구분해 명령이 미완료 상태로 남지 않게 한다. 자동 재시도는 중복 판정 위험 때문에 하지 않는다.
- 낭독 버튼을 프로세스 재시작 후에도 라우팅하고, 재시작 전 투표는 초기화된다는 점을 표시한다. 오래된 위치의 버튼은 시간 초과 대신 이미 이동했다는 응답을 받게 한다.
- 시나리오 완료 응답과 `/시나리오조회`의 완료 표시를 확인한다.
- Docker Compose가 SQLite named volume을 사용하도록 정식화해 호스트 파일 바인드 마운트 재사용을 막는다.
- 성공/실패 및 오류 경로의 자동화 테스트와 원인·실행 증거 문서를 유지한다.

## 제약과 비목표

- 새 서비스나 패키지는 추가하지 않는다.
- 배포하지 않는다. 테스트는 로컬 Docker와 테스트 채널에서 한다.
- 모델은 주사위 결과, 기능값, 분기 문구를 만들어내지 않는다.
- 규칙 없는 기존 시나리오는 낭독과 명령을 계속 지원하되, 자동 규칙 매칭을 가장하지 않는다.
- Discord 외부 계정의 인증 키 회전은 코드 변경 범위에 포함하지 않는다. 이전 진단 출력에 노출된 키는 사용자가 제공자 대시보드에서 교체해야 한다.

## 주요 파일

- `scenario_parser.py`: 선택적 장면 규칙 파싱, 기존 문서 호환.
- `intent_analyzer.py`: 규칙 후보를 입력으로 받고 등록된 규칙 ID만 반환하도록 프롬프트/검증.
- `bot/cogs/action.py`: 현재 시나리오와 PC 기능값 조회, 결과 굴림 및 분기 서술, 외부 API 오류 응답.
- `storage.py`, `bot/cogs/narration.py`, `bot/main.py`: 재시작 뒤 낭독 버튼 등록, 완료 위치 처리.
- `bot/embeds.py`: 장면 분기/완료를 독자가 확인할 수 있는 응답.
- `compose.yaml`, `README.md`: 로컬 named volume 실행 절차.
- `tests/`: parser, action, failure, narration persistence, scenario completion 검증.

## 동작 세부 규칙

### 판정 규칙

구조화 규칙은 고정 ID, CoC 기능명, 성공/실패 서술을 가진다. 모델은 현재 장면 후보 중 ID 하나를 고르는 역할만 한다. 코드가 장면에 존재하는 ID인지, 기능이 등록된 CoC 기능인지 확인한 뒤 캐릭터 시트 값을 가져와 굴린다. 모델 confidence가 0.6 미만이거나 매칭 없음, 규칙 ID/기능 불일치, 시트 값 없음이면 굴리지 않고 수동 `/판정` 사용을 안내한다.

`dice.determine_success_level()`의 등급을 그대로 사용한다. `critical`, `extreme`, `hard`, `regular`는 성공 문구를, `fail`, `fumble`은 실패 문구를 출력한다. 규칙 후보가 여러 개여도 모델이 지정한 정확한 ID 하나만 사용하고, 후보가 없거나 응답 ID가 모호/미등록이면 굴리지 않는다. 결과 문구는 규칙 데이터에서 가져오며 모델이 새 분기 문구를 만들지 않는다.

### 모델 오류

`/행동`은 provider 오류를 재시도하지 않는다. 인증/권한 오류, 요청 제한(429), 서비스 오류(5xx), 네트워크/제한시간, 빈 응답, 안전 필터 차단, 잘못된 JSON/스키마 응답을 각각 안전한 사용자 안내로 종료한다. 사용자 안내와 로그에는 비밀 키 및 전체 프롬프트/응답 본문을 포함하지 않는다. 알 수 없는 provider 오류도 일반 오류 안내로 종료한다.

### 낭독 지속성

시작 시 저장된 모든 시나리오의 모든 낭독 위치에 대해 persistent callback을 등록한다. Discord custom ID에는 시나리오 ID와 문장 위치를 담는다. 이는 재시작 전에 만들어진 오래된 버튼도 callback에 전달하기 위함이다. callback은 DB의 현재 위치를 다시 확인하고 값이 다르면 이미 이동했다는 ephemeral 응답을 한다. 위치마다 중복 등록하지 않는다. 투표는 프로세스 메모리에만 있으므로 재시작 직후 새 투표로 시작한다. Keeper와 PC가 같은 Discord ID를 사용하면 고유 사용자 1명으로 세며, 1명이 투표하면 진행된다. 이 동작은 UI 안내 및 테스트에 명시한다.

### SQLite named volume 및 데이터 이전

Compose는 `coc-bot-data`라는 명시적 named volume을 `/app/data`에 연결한다. 기존 환경에서 같은 이름의 volume이 있으면 재사용한다. 새 환경에서 빈 volume이면 기존 bind-mount DB를 자동으로 발견하거나 복사하지 않는다. 기존 `./data/coc-bot.sqlite3`를 이전해야 할 때는 봇을 중지하고 SQLite backup API로 백업 파일을 만든 다음, named volume에 복사하고 무결성을 검사한다. 실행 중인 DB/WAL 파일을 단순 파일 복사하지 않는다. 스키마는 기존 `create_pool` 초기화 로직이 업그레이드하며, 별도 파괴적 초기화를 하지 않는다.

### 시나리오 입력 호환성

기존 시나리오의 Google Docs export HTML은 `h1/h2/h3/p` 기반 낭독 추출을 그대로 유지한다. 규칙은 장면 아래의 고정 제목 `Checks`와 표준 HTML 표 행(`id`, `skill`, `action`, `success`, `failure`)으로만 읽으며, 표가 보존되지 않은 export 또는 제목이 없는 문서는 기존 낭독만 제공한다. Markdown은 저장소에 별도 Markdown parser가 없으므로 직접 parser 입력으로 취급하지 않는다. 시나리오 테스트 fixture에는 실제 Docs export와 같은 heading/paragraph/table 구조를 넣는다.

## 완료 기준

- 시나리오 규칙이 포함된 실제 파서 입력에서 올바른 판정·결과를 얻고, 기존 규칙 없는 입력도 파싱된다.
- 시나리오 문맥이 `/행동` 분석 호출에 전달되고, 식별된 규칙은 지정 기능값과 주사위 결과를 사용한다.
- 성공/실패가 해당 규칙의 문구로 채널 응답에 반영된다. 알 수 없는 규칙 ID나 Gemini 오류는 굴림 없이 사용자 안내로 끝난다.
- 테스트에서 503, 시간 제한, 잘못된 응답, 미등록 기능, 동일 계정 투표, 중복/낡은 투표, 재시작 뒤 재개 및 완료 상태를 확인한다.
- 로컬 Docker는 named volume을 사용하고 헬스체크 및 SQLite 무결성 검사가 통과한다.
- 전체 자동화 테스트와 정리된 재현 보고서가 있다.
